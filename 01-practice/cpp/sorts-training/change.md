## 一、`SortString.cpp` – 实现字符串排序函数 & 思考题

### 1. `BubbleA` – 数组指针版冒泡排序（二维字符数组）

**原代码**：函数体为空，仅有一条 `cout` 提示。

**实现逻辑**：
- 参数 `char (*str)[NUM]` 是指向长度为 `NUM` 的字符数组的指针，即二维数组的行指针。
- `str[i]` 等价于二维数组的第 i 行，每个“行”是一个长度最多 `NUM-1` 的 C 字符串。
- 数据来源 `strA` 是 `char[][NUM]` 类型的局部二维数组，所有字符串存储在**栈区**，内容可读写。
- 比较字符串内容用 `strcmp`，交换内容用 `strcpy` + 临时缓冲区 `char temp[NUM]`。
- 采用经典冒泡排序：外层 `size-1` 轮，内层每轮比较相邻元素并交换。

**边界考虑**：
- `NUM=20`，实际字符串均远短于此，`strcpy` 不会越界。
- 临时数组 `temp[NUM]` 在栈上分配，对于 `NUM=20` 内存开销可忽略。
- `size <= 1` 时外层循环不执行，自然正确处理。

### 2. `BubbleB` – 指针数组版冒泡排序（`char*[]` 数组）

**原代码**：函数体为空，仅有一条 `cout` 提示。

**实现逻辑**：
- 参数 `char *str[]` 是指针数组，每个元素是一个 `char*`，指向某处字符串的首地址。
- 数据来源有三种情况：
  - `strB`：指针指向**只读数据区**的字符串字面常量（如 `"enter"`），**不可修改字符串内容**，否则触发段错误。
  - `strC` / `strD`：通过 `GetStrings` 在**堆区** `new` 出来的字符串，内容可读写。
- 为保证通用性（适应 `strB` 这种不可写场景），**只交换指针值**，不交换字符串内容。
- 比较仍用 `strcmp`（比较指针所指向的字符串内容），交换用临时指针 `char *temp`。

**边界考虑**：
- `size <= 1` 时外层循环不执行，正确。
- 交换指针是 O(1) 操作，比 `strcpy` 交换内容更高效。
- 不存在栈溢出或越界风险。

### 3. 四道思考题（在代码中以注释形式作答）

#### Q1：`strA`、`strB`、`strC`、`strD` 的字符串内容分别在内存的什么区域？

| 变量 | 声明方式 | 字符串存储区域 | 是否可写 |
|------|----------|---------------|---------|
| `strA` | `char strA[][NUM]` | **栈区**（局部二维数组） | 可写 |
| `strB` | `char *strB[]` | **只读数据区**（`.rodata`，字符串字面常量） | 不可写 |
| `strC` | `char **strC`（由 `GetStrings` 分配） | **堆区**（`new char[]` 逐个分配） | 可写 |
| `strD` | `char **strD`（由 `GetStrings` 分配） | **堆区**（同 `strC`） | 可写 |

**关键区别**：`strB` 的指针本身在栈上，但指针指向的字符串字面常量在只读区，这是 `BubbleB` 必须交换指针而非交换内容的根本原因。

---

#### Q2：关于字符串排序的三个子问题

**(1) 如何比较两个字符串的内容？**
- 使用 C 标准库 `<cstring>` 中的 `strcmp(s1, s2)`。
- 返回值 `< 0` 表示 `s1 < s2`，`== 0` 表示相等，`> 0` 表示 `s1 > s2`。
- 不能用 `==`、`<`、`>` 直接比较 `char*`，因为那比较的是指针地址而非内容。

**(2) 存储在什么区域的字符串能交换其内容？**
- **栈区**（局部 `char` 数组）和**堆区**（`new`/`malloc` 分配）上的字符串可以交换内容，因为这些内存页面具有读写权限。
- **只读数据区**（字符串字面常量如 `"hello"`）上的字符串**不可修改**，试图写入会触发访问违例（segmentation fault）。

**(3) 若不能交换字符串的内容，排序操作中交换什么？**
- 交换**指针数组中的指针值**：不修改字符串本身，只改变指针的指向关系。
- 排序后，指针数组中的指针按字符串字母序排列，但各字符串在原位不动。
- 这种方式的额外好处是交换开销为 O(1)，与字符串长度无关。

---

#### Q3：`GetStrings` 为什么要设计成函数模板？两次调用时 `T` 分别实例化成什么？

**原因**：函数需要同时兼容两种不同的源数据类型：
- `strA` 的类型是 `char[12][20]`，传递给函数时退化为 `char (*)[20]`（指向长度为 20 的 char 数组的指针），`source[i]` 是 `char[20]`。
- `strB` 的类型是 `char*[12]`，传递给函数时退化为 `char**`，`source[i]` 是 `char*`。

C++ 中 `char (*)[20]` 和 `char**` 是两种**不兼容的类型**，无法用同一个非模板函数的形参同时接收。通过函数模板，编译器根据实参类型自动推导并实例化：

| 调用 | 实参 `source` 的类型 | 模板参数 `T` 实例化为 |
|------|---------------------|---------------------|
| `GetStrings(strC, strA, n1)` | `char (*)[20]` | `char[20]` |
| `GetStrings(strD, strB, n2)` | `char**` | `char*` |

模板展开后，两次调用生成两个不同的函数实例，各自处理对应的类型。

---

#### Q4：`GetStrings` 和 `FreeStrings` 的第一个参数为什么使用引用型二级指针（`char **&`）？如果不用会有什么后果？

**为什么要用引用**：
- `GetStrings` 需要在函数内部 `new char*[n]`，并将分配到的堆地址**回传给调用者**的 `strC`/`strD`。
- `FreeStrings` 需要在释放所有内存后，将调用者的指针**置为 `NULL`**，避免成为野指针。
- 如果参数写成 `char **dest`（去掉 `&` 引用），函数接收的是实参的**副本**，对副本的赋值不影响调用者的原指针。

**不用引用的后果**：

| 函数 | 后果 |
|------|------|
| `GetStrings` | `dest = new char*[n]` 只修改了局部副本，调用者的 `strC`/`strD` 仍为 `NULL`。新分配的内存地址丢失，**无法 `delete`，造成内存泄漏**。 |
| `FreeStrings` | `strs = NULL` 只把局部副本置空，调用者的指针仍指向已释放的内存，成为**野指针**。后续任何对该指针的访问（读/写/`delete`）都是未定义行为。 |

## 二、`Sorts.h` – 修复 `Qsort` 栈溢出 & 最坏情况退化

### 原代码问题

```cpp
// 原始版本（有问题的）
template <typename T> void Qsort(T *a, int size)
{
    T pivot, temp;
    int left=0, right=size-1;

    if(size<=1) return;

    pivot = a[right];              // 总是取最后一个元素为 pivot
    // ... 分区逻辑 ...
    Qsort(a, left);                // 递归左侧
    Qsort(a+left+1, size-left-1);  // 递归右侧
}
```

**问题一：pivot 选末尾元素，有序/逆序数据退化为 O(n²)**
- 当数据完全升序（如 `[0,1,2,...,n-1]`）时，末尾元素是最大值，分区后左侧 `n-1` 个元素、右侧 0 个。
- 当数据完全降序时，末尾元素是最小值，分区后左侧 0 个、右侧 `n-1` 个。
- 每轮只减少 1 个元素，时间复杂度 O(n²)，递归深度 = n。

**问题二：双递归导致栈深度不可控**
- 两个递归调用无条件执行，递归深度等于递归树的深度。
- 对于有序/逆序数据，深度 = n。当 `n=65536` 时，每个栈帧约几十字节，总栈消耗远超默认栈大小（Windows 默认 1MB），导致**栈溢出崩溃**。

**原项目的临时规避**：`Main.cpp` 中判断 `n==65536 && 有序/逆序` 时跳过快速排序。但这不是真正的解决方案。

---

### 修复方案

```cpp
// 修复后的版本
template <typename T> void Qsort(T *a, int size)
{
    T pivot, temp;
    int left, right;

    while(size > 1)                          // 用循环代替最外层递归
    {
        // 取中间元素作 pivot，避免有序时退化为 O(n²)
        temp = a[size/2];
        a[size/2] = a[size-1];
        a[size-1] = temp;

        pivot = a[size-1];
        left = 0;
        right = size-1;
        // ... 分区逻辑（不变）...
        a[size-1] = a[left]; a[left] = pivot;

        // 递归短的，长的用循环，深度 O(log n)
        if(left < size-left-1)
        {
            Qsort(a, left);                  // 递归较短的一半
            a = a + left + 1;                // 较长的一半用循环迭代
            size = size - left - 1;
        }
        else
        {
            Qsort(a+left+1, size-left-1);
            size = left;
        }
    }
}
```

**修复一：pivot 取中间元素**

将 `a[size/2]`（中间位置元素）与 `a[size-1]`（末尾元素）交换，再以末尾元素为 pivot。效果等同于以中间元素为 pivot，但无需改动分区逻辑。

对于有序数组 `[0,1,2,3,4]`，`mid = a[2] = 2`，分区为 `[0,1]` 和 `[3,4]`，均匀二分。
对于逆序数组 `[4,3,2,1,0]`，`mid = a[2] = 2`，分区同样均匀。
时间复杂度恢复为期望 O(n log n)。

**修复二：while 循环消除尾递归**

- 外层用 `while(size > 1)` 替代 `if(size<=1) return`，持续迭代处理。
- 每次分区后，比较左右两半的大小：
  - 对**较短的一半**调用递归 `Qsort`。
  - 对**较长的一半**，通过修改 `a` 和 `size` 在下一轮 `while` 循环中继续处理。
- 递归深度 ≤ ⌈log₂ n⌉。`n=65536` 时深度不超过 16，栈消耗极小，彻底杜绝栈溢出。

**为什么深度是 O(log n)**：因为每次只对较小的一半递归，较小的一半的长度 ≤ 当前长度的一半。递归链上每一层处理的长度至少减半，最深路径长度为 log₂ n。

## 三、`Main.cpp` – 移除 Qsort 跳过逻辑

### 原代码中的 workaround

原 `Test` 函数中有三处判断 `n==65536 && j<=0 && i==m-1`（即数据规模 65536、完全顺序或完全逆序、快速排序算法），分别做了：
1. **`break`** 跳过该算法的执行。
2. 时间列输出**空白**。
3. 正确性列输出**“快速排序：由于递归层次太深，可能导致栈溢出，故跳过。”**

这是对 Qsort 缺陷的临时规避，不是真正的解决方案。

### 改动

因 Qsort 已修复（中间 pivot + 尾递归消除），上述三处特殊判断全部移除，恢复统一的循环逻辑。现在所有数据分布（完全逆序、完全顺序、均匀分布、正态分布）和所有规模（1024 ~ 65536）下，三种排序算法均被正常执行和计时。

### 改动的代码位置（三处）

```cpp
// 1. 执行循环 – 移除 break 跳过（原 Main.cpp 第 54-55 行）
for(i=0; i<m; i++)
```

## 四、边界条件与大数据量考量总结

| 考量点 | 处理方式 |
|--------|---------|
| 空数组 / 单元素数组 | 所有排序函数通过循环条件（`i<size`、`size>1`）自然处理，不做无操作。 |
| 完全有序 / 逆序数据 | Qsort 取中间 pivot 后均匀分区，不再退化。 |
| 大量重复元素 | 分区时 `<=` 和 `>=` 让等值元素不移动，不会死循环。 |
| Qsort 递归过深 | 尾递归消除 + 短边递归，深度严格 O(log n)。 |
| `BubbleB` 写入只读内存 | 改交换内容为交换指针，避免段错误。 |
| `GetStrings` 内存分配失败 | `new` 失败会抛 `std::bad_alloc`，程序终止（训练项目中可接受）。 |
| `FreeStrings` 野指针 | 释放后将指针置 `NULL`，防止重复释放或误用。 |
